## 一、摘要（Abstract）

1. **研究背景与问题**

   - 足球比赛中裁判判罚具有**主观性强、争议多**的特点，VAR 虽然提供多视角回放，但决策过程仍不透明。
   - 现有足球视频分析多集中在**动作识别、事件检测、结果预测**，较少面向普通用户给出**带规则依据的通俗解释**。
   - 多模态大模型与检索增强生成（RAG）的发展，使「**视频理解 + 规则文本 + 对话式说明**」在同一应用内落地成为可能。

2. **研究目标与思路**

   - 在**已有的 X-VARS / Video-ChatGPT 类多模态足球判罚演示工程**上，扩展一套**面向足球规则文本的 RAG 模块**，构建可本地运行的智能裁判助手原型。
   - 系统能力目标：
     - 从短视频中抽取视觉特征并与大模型对齐；
     - 结合用户提问，从规则库中**检索相关条款**并写入提示；
     - 生成**有规则上下文支撑**的文字回答，并支持多轮追问（界面层）。
   - 整体路径：**CLIP 视觉塔提取视频特征 → 时空压缩与多模态对齐（沿用原工程）→ RAG 检索规则条文并增强问题文本 → 多模态 LLM 生成解释**。

3. **主要贡献（与“原项目 + RAG”实际一致）**

   - **工程集成**：在现有多模态管线中**系统化接入 RAG**（规则分块、向量索引、检索与 prompt 拼接），形成「先检索规则、再生成解释」的交互流程，并以 Streamlit 等形态**可复现演示**。
   - **领域适配**：针对足球竞赛规则场景设计**知识库组织方式与检索–生成衔接策略**（如参考条款注入、Top-K 控制、与视频 token 长度的配合），提升回答**可溯源性**（相对无 RAG 的纯生成）。
   - **方法边界说明**：**不主张**在本工作中从头提出新的视觉骨干或全新多模态架构；**视觉–语言主干与时空特征融合**以原开源 / 项目方案为主，**本文增量聚焦于规则侧的 RAG 与系统层设计**。

4. **实验与验证（实事求是）**

   - 若暂无大规模公开基准上的完整实验：**以案例分析、消融（开/关 RAG）、简单人工或指标预留**为主，说明 RAG 在「规则引用、措辞专业性」上的**定性或小规模**变化；
   - **可写为**「未来工作」：在 SoccerNet-XFoul 等数据上补充分类 / 生成指标（Accuracy、F1、BLEU、ROUGE）及系统消融。避免在摘要中承诺**尚未完成**的量化结论。

## 二、介绍（Introduction）

1. **研究背景：为什么要做这个项目？**

   - 足球比赛节奏快，对抗激烈，很多判罚场景难以通过单次回放就达成共识。
   - 现有 VAR 主要提供**画面证据**，**结构化文字理由**对公众与教育场景仍不足。
   - 多模态对话系统若**不接入**权威规则文本，容易产生「常识化」回答而**难以对照具体条款**，RAG 可减轻这一问题。

2. **文献综述（可按“视频分析 / 多模态大模型 / RAG”分述）**

   - 足球视频分析：多侧重**标签或分数**，可解释的自然语言说明相对少。
   - Video-ChatGPT 等：**视频 token + LLM** 擅长开放式描述，但**规则密集领域**仍需外部知识注入。
   - RAG：在法律、医疗等文本任务中已验证可提升**可信度**；与**足球短视频 + 中文规则**结合的**完整开源演示**仍可作为清晰的课程/工程课题贡献。

3. **研究问题与创新点（对齐实际工作量）**

   - **研究问题**：
     - 如何在**尽量不改动原有视觉–语言主干**的前提下，将足球规则库以**可维护、可检索**的方式并入多模态判罚问答？
     - 检索结果如何**稳定写入 prompt**，并与视频占位符、对话模板**兼容**？
   - **创新点（宜写法）**：
     - **RAG 与多模态判罚流水线的闭环集成**（非单独文本 chatbot）。
     - **面向裁判规则的知识库与检索策略**在工程上的具体化（分块、嵌入、缓存、失败回退等，以实装为准）。
     - 若与「原仓库无 RAG」对比：**明确写出差异为「增加 RAG 分支与 UI」**，避免把基线能力全部写成本文首次提出。

4. **论文结构安排**

   - 第 3 章：相关技术（CLIP、Video-ChatGPT 式多模态 LLM、RAG）。
   - 第 4 章：**原系统流程简述 + 本文新增的 RAG 设计与实现**。
   - 第 5 章：实验或评测方案（**与当前可完成程度一致**）。
   - 第 6 章：总结与展望。

## 三、相关技术（Related Techniques）

> 重点：三类技术各自是什么 → 在本项目中**分别承担什么角色** → RAG 补上了原方案的哪块短板。

1. **CLIP 与视觉编码**

   - 对比学习图像–文本对齐；本演示采用 **ViT-L/14** 视觉塔（与原工程一致）。
   - 时序上采用**帧采样 + 时空池化 / 定长序列**，将视频变为固定长度的视觉 token 序列供 LLM 使用（**继承原项目实现**）。

2. **视频多模态 LLM（Video-ChatGPT 路线）**

   - **投影层 + 占位符注入**：视觉特征进入与词向量同一解码器栈（因果自回归生成）。
   - **本文不重新推导该架构**，仅说明其与下游 RAG 的接口：**文本侧 prompt 可额外拼接规则片段**。

3. **RAG**

   - 从规则库检索与问题相关的段落，**增强用户问题或 system / user 模板**，再交给多模态 LLM。
   - 本项目特点：检索触发基于**用户问题**（及可选扩展）；视频侧特征**独立提取**，与「纯文本 RAG」的差异在**系统编排**一章说明。

## 五、实验（Experiments）

**本节标题可调整为「实验与评价设想」或保留「实验」但措辞与**当前数据**一致。**

1. **实验目标（务实）**

   - 验证在**同一模型与同一批视频**上，**开启 RAG 与关闭 RAG** 时：
     - 生成文本是否更常出现**与规则库一致的表述或条款指向**；
     - 是否存在**冗余、检索噪声**或**长度导致的退化**（诚实讨论）。
   - 若仅有个例：**以定性分析 + 截图/附录对话**为主，摘要中不夸大统计显著性。

2. **数据集与任务（建议写法）**

   - **主文**：自建或课程提供的**若干短视频 + 固定问题集**，或公开片段的子集；
   - **可选：未来工作**—— SoccerNet-XFoul 等上的**动作/严重程度分类**与**开放生成评测**（需另行实现 Accuracy、F1、BLEU、ROUGE 等脚本）。
   - 避免写「本文已在 XFoul 上全面超越 SOTA」除非**确有实验表格支撑**。

3. **评估方式**

   - **消融**：`use_rag = true/false`；可辅以不同 Top-K；
   - **自动指标（若有参考答案）**：BLEU、ROUGE —— **仅在实际跑出结果后写入**；
   - **人工**：合理性、是否引用规则、可读性（小规模问卷即可）；
   - **基线**：无 RAG 的同模型同参数，优于「换多个 SOTA 模型」若未做则不必写。

4. **结果分析**

   - RAG 带来的**收益与失败模式**（检索错误、规则片段过长、与视频事实脱节等）；
   - 系统局限：依赖规则库质量、嵌入模型语种、算力与延迟。
